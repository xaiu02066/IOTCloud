# 智慧农业环境监控平台 · 部署说明书

> 适用项目：IOTCloud（Flask 后端 + 物联网依赖服务）
> 仓库：GitHub `xaiu02066/IOTCloud` ／ Gitee `xie-yongHappy/test`
> 文档版本：2026-09-02（与 `app/config.py` 一致）

---

## 1. 文档说明

本文档描述 **智慧农业环境监控平台** 后端服务的部署流程，覆盖：

- 源码获取与运行环境准备
- 虚拟环境与依赖安装
- 环境变量（`.env`）配置
- 依赖中间件启动（MySQL / InfluxDB / Redis / EMQX）
- 数据库初始化
- 本地开发启动与生产环境部署（gunicorn + nginx）
- 健康检查、排错与安全建议

> ⚠️ 当前代码状态：后端为**骨架 + F1 用户管理（注册/登录/JWT）**。F2–F9 尚未实现；涉及数据库读写的功能（如注册/登录）需先启动 MySQL 并正确配置 `DATABASE_URL` 后方可使用。

## 2. 环境要求

| 组件 | 版本要求 | 说明 |
|------|----------|------|
| Python | ≥ 3.13 | 项目使用托管 Python 3.13.12 开发；虚拟环境内为 3.13.14 |
| pip | 随 Python 提供 | 用于安装依赖 |
| Git | ≥ 2.40 | 用于拉取源码、管理远程 |
| MySQL | ≥ 8.0 | 业务数据（用户/产品/设备/权限/告警） |
| InfluxDB | ≥ 2.x | 时序数据（F5 遥测） |
| Redis | ≥ 7.0 | 缓存 / 限流 / 告警去重（F8） |
| EMQX | ≥ 5.x | MQTT Broker（F5 上报 / F6 指令） |
| Docker（可选） | ≥ 24 | 推荐用 docker-compose 一键拉起上述中间件 |
| Nginx（生产可选） | ≥ 1.24 | 反向代理 + 静态资源 + HTTPS |

> 说明：应用启动**不会主动连接** MySQL/InfluxDB/Redis/EMQX，因此不启动这些服务也能 `python run.py` 启动（仅 `/` 与 `/health` 可用）。真正执行业务时再启动依赖即可。

## 4. 后端部署

### 4.1 创建虚拟环境并安装依赖

```bash
# 在项目根目录
python -m venv venv

# 激活虚拟环境
#   Windows (Git Bash / PowerShell):
source venv/Scripts/activate        # Git Bash
#   venv\Scripts\activate            # PowerShell / CMD

# 安装依赖（requirements.txt 已锁定版本）
pip install -U pip setuptools wheel
pip install -r requirements.txt
```

依赖包含：Flask、Flask-Cors、Flask-JWT-Extended、Flask-SQLAlchemy、PyMySQL、Flask-SocketIO、Flask-Caching、redis、paho-mqtt、influxdb-client、python-dotenv、gunicorn。

### 4.2 配置环境变量（`.env`）

复制样例并填入实际值（**`.env` 已被 `.gitignore` 忽略，切勿提交**）：

```bash
cp .env.example .env
```

完整参数表（与 `app/config.py` 一一对应）：

| 变量 | 默认值 | 必改 | 说明 |
|------|--------|------|------|
| `FLASK_CONFIG` | `development` | 否 | 运行环境：`development` / `production` |
| `SECRET_KEY` | `dev-secret-change-me` | **是** | Flask 签名/会话密钥，生产必须替换为随机串 |
| `DATABASE_URL` | `mysql+pymysql://root:root@localhost:3306/iotcloud?charset=utf8mb4` | **是** | SQLAlchemy 连接串（MySQL） |
| `JWT_SECRET_KEY` | `dev-jwt-secret-change-me` | **是** | JWT 签名密钥，生产必须替换 |
| `INFLUXDB_URL` | `http://localhost:8086` | 否 | InfluxDB 地址（F5 用） |
| `INFLUXDB_TOKEN` | （空） | 否 | InfluxDB 令牌（F5 用） |
| `INFLUXDB_ORG` | `iotcloud` | 否 | InfluxDB 组织 |
| `INFLUXDB_BUCKET` | `telemetry` | 否 | 时序数据桶名 |
| `REDIS_URL` | `redis://localhost:6379/0` | 否 | Redis 连接串 |
| `MQTT_BROKER` | `localhost` | 否 | EMQX 主机（F5/F6 用） |
| `MQTT_PORT` | `1883` | 否 | MQTT 端口 |
| `MQTT_CLIENT_ID` | `iotcloud-backend` | 否 | MQTT 客户端 ID |
| `CORS_ORIGINS` | `*` | 否 | 允许跨域的前端来源（同时用于 SocketIO） |

> 注：`JWT_ACCESS_TOKEN_EXPIRES`（2h）、`JWT_REFRESH_TOKEN_EXPIRES`（7d）、`CACHE_TYPE=RedisCache` 等在代码中固定，未暴露为环境变量。

生成随机密钥示例：

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

### 4.3 启动依赖中间件（推荐 docker-compose）

在本地或服务器用 docker-compose 一键拉起 MySQL / InfluxDB / Redis / EMQX（以下为参考配置，可按需调整）：

```yaml
# docker-compose.yml（参考，非仓库内置）
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: iotcloud
    ports: ["3306:3306"]
    volumes: ["mysql_data:/var/lib/mysql"]
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci

  redis:
    image: redis:7
    ports: ["6379:6379"]

  influxdb:
    image: influxdb:2.7
    environment:
      DOCKER_INFLUXDB_INIT_MODE: setup
      DOCKER_INFLUXDB_INIT_ORG: iotcloud
      DOCKER_INFLUXDB_INIT_BUCKET: telemetry
      DOCKER_INFLUXDB_INIT_ADMIN_TOKEN: <你的token>
    ports: ["8086:8086"]
    volumes: ["influx_data:/var/lib/influxdb2"]

  emqx:
    image: emqx:5
    ports: ["1883:1883", "8083:8083", "8084:8084", "18083:18083"]

volumes:
  mysql_data:
  influx_data:
```

```bash
docker compose up -d
```

启动后请确认：
- MySQL 已建库 `iotcloud`（或手动 `CREATE DATABASE iotcloud CHARACTER SET utf8mb4;`）
- InfluxDB 已建组织 `iotcloud`、桶 `telemetry`，并拿到 admin token 填入 `INFLUXDB_TOKEN`
- EMQX 控制台 http://localhost:18083 可访问

### 4.4 初始化数据库（建表）

当前未引入数据库迁移工具（Flask-Migrate）。首次部署用 `db.create_all()` 建表：

```bash
# Linux / macOS
export FLASK_APP=run.py
# Windows (PowerShell)
$env:FLASK_APP = "run.py"

flask shell
>>> from app.extensions import db
>>> db.create_all()
>>> exit()
```

或更直接的脚本方式：

```bash
flask shell <<'PY'
from app.extensions import db
db.create_all()
PY
```

> 后续建议引入 Flask-Migrate（`flask db init/migrate/upgrade`）管理表结构变更，避免手动 `create_all` 覆盖风险。

### 4.5 本地开发启动

```bash
# 确保已激活 venv，且 .env 已配置
python run.py
```

启动后监听 `0.0.0.0:5000`（debug 模式，代码改动自动热重载）。验证：

```bash
curl http://127.0.0.1:5000/health
# => {"status":"ok","service":"iotcloud"}
```

### 4.6 生产环境启动

生产使用 gunicorn 托管 WSGI：

```bash
# 设置生产环境
export FLASK_CONFIG=production        # Windows: $env:FLASK_CONFIG="production"

# 标准启动（4 工作进程）
gunicorn -w 4 -b 0.0.0.0:5000 run:app
```

> ⚠️ **实时推送（F7）提示**：当启用 Flask-SocketIO 实时推送时，gunicorn 需使用 gevent-websocket 工作进程（需额外安装 `gevent-websocket`），且工作进程数建议为 1：
> ```bash
> pip install gevent-websocket
> gunicorn -k geventwebsocket.gunicorn.workers.GeventWebSocketWorker -w 1 -b 0.0.0.0:5000 run:app
> ```
> 当前 F7 未实现，先用标准 worker 即可。

#### systemd 服务示例（Linux 服务器）

`/etc/systemd/system/iotcloud.service`：

```ini
[Unit]
Description=IOTCloud Flask Backend
After=network.target mysql.service redis.service

[Service]
User=www-data
WorkingDirectory=/opt/IOTCloud
Environment=FLASK_CONFIG=production
EnvironmentFile=/opt/IOTCloud/.env
ExecStart=/opt/IOTCloud/venv/bin/gunicorn -w 4 -b 0.0.0.0:5000 run:app
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now iotcloud
```

## 5. 反向代理（Nginx，生产可选）

将 5000 端口通过 Nginx 暴露，并启用 HTTPS 与 WebSocket 升级：

```nginx
server {
    listen 80;
    server_name iot.example.com;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket（F7 实时推送需要）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

配置后 `sudo nginx -t && sudo systemctl reload nginx`。

## 7. 健康检查与验证

| 项目 | 方法 | 期望 |
|------|------|------|
| 服务存活 | `GET /health` | `{"status":"ok","service":"iotcloud"}` (200) |
| 根路由 | `GET /` | 平台信息 JSON (200) |
| 用户注册 | `POST /api/auth/register` | 成功写入 MySQL；失败多为 `DATABASE_URL` 不通 |
| 用户登录 | `POST /api/auth/login` | 返回 `access_token` / `refresh_token` |

示例：

```bash
curl -X POST http://127.0.0.1:5000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"secret123","email":"alice@example.com"}'

curl -X POST http://127.0.0.1:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"secret123"}'
```

## 8. 常见问题与排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `sqlalchemy.exc.OperationalError: Access denied for user 'root'@'localhost'` | MySQL 未启动或 `DATABASE_URL` 账号/密码错误 | 启动 MySQL，核对 `.env` 中 `DATABASE_URL` |
| `Can't connect to MySQL server` | MySQL 地址/端口不通 | 确认 MySQL 在 `3306` 监听，容器端口已映射 |
| 注册/登录 500 但 `/health` 正常 | 数据库未初始化或连不上 | 见 4.4 初始化库，并查 MySQL 可达性 |
| gunicorn 启动后 WebSocket 不工作 | 未用 gevent-websocket worker | 见 4.6 F7 提示 |
| `ModuleNotFoundError` | 依赖未装或 venv 未激活 | 激活 venv，`pip install -r requirements.txt` |
| `.env` 修改不生效 | 未重启服务 | 重启 `run.py` / gunicorn |

## 9. 安全建议

1. **立即替换密钥**：`SECRET_KEY`、`JWT_SECRET_KEY` 必须改为随机串，禁止沿用默认值。
2. ** secrets 不入库**：`.env` 已被忽略；切勿把含令牌的 `.env` 提交到 GitHub/Gitee。
3. **生产关闭 DEBUG**：使用 `FLASK_CONFIG=production`。
4. **CORS 收敛**：生产将 `CORS_ORIGINS` 设为具体前端域名，不要用 `*`。
5. **数据库最小权限**：为应用单独建 MySQL 用户，仅授予 `iotcloud` 库必要权限。
6. **HTTPS**：对外服务务必经 Nginx/TLS 终止，禁止明文暴露 5000。
7. **令牌管理**：GitHub/Gitee 的 Personal Access Token 用毕即吊销。
