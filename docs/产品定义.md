# 产品定义文档

> 智慧农业环境监控平台 · 产品（Product）领域说明
> 适用范围：F2 产品管理，对应数据库 `products` 表、API 前缀 `/api/products`

---

## 1. 什么是"产品"

在物联网平台中，**产品**是"同一型号 / 同一固件 / 同一物模型"的设备的**抽象模板**。把设备按产品归类后，平台只需定义一次物模型（属性/服务/事件），该产品的所有设备即可共享同一套能力描述与接入逻辑。

- 一个产品 = 一种设备型号（如"智能环境测控仪"）。
- 一个产品下可挂载**多台**具体设备（Device），设备继承产品的物模型。
- 产品的核心元数据存于 MySQL（业务库），设备的**实时时序数据**走 InfluxDB，不在此库。

---

## 2. 产品核心字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `product_key` | string(64) | 是 | 产品标识（唯一），设备与云端交互、Topic 拼接的关键，如 `env_ctrl` |
| `product_name` | string(128) | 是 | 产品展示名称，如 `智能环境测控仪` |
| `description` | string(255) | 否 | 产品定位 / 描述，如 `集数据采集与设备控制于一体的农业物联网终端` |
| `protocol` | string(32) | 否 | 接入协议，默认 `MQTT` |
| `thing_model` | JSON | 否 | 完整物模型快照（属性+服务+事件），前端一次加载用 |
| `created_at` / `updated_at` | datetime | 自动 | 创建 / 更新时间 |

> 注：`product_key` 具有唯一约束，创建 / 更新时若与已有产品冲突会返回 `409`。

---

## 3. 与物模型、设备的关系

```
Product (产品)
  │  1
  ├─── *  ProductProperty   (属性定义)
  ├─── *  ProductService    (服务定义)
  ├─── *  ProductEvent       (事件定义)
  │
  │  1
  └─── *  Device (设备)  ← 实际物理设备，继承产品物模型
```

- **产品 → 物模型（1∶N）**：一个产品包含多个属性 / 服务 / 事件定义。
- **产品 → 设备（1∶N）**：一个产品下挂载多台设备；设备通过 `product_id` 关联产品。
- 删除产品时，其下属的物模型定义（属性/服务/事件）会被**级联删除**（`cascade="all, delete-orphan"`）。

---

## 4. 示例：智能环境测控仪（env_ctrl）

| 项目 | 内容 |
|------|------|
| 产品名称 | 智能环境测控仪 |
| 产品标识 | `env_ctrl` |
| 产品定位 | 集数据采集与设备控制于一体的农业物联网终端 |
| 接入协议 | MQTT |
| 物模型 | 6 属性 + 2 服务 + 4 事件（详见《物模型定义文档》） |

该产品的 `thing_model` JSON 字段已写入完整物模型快照，前端调用 `GET /api/products/<id>/thing-model` 即可一次获取产品元数据与全部物模型定义。

---

## 5. 生命周期

1. **创建**：平台管理员定义产品（指定 `product_key`、`product_name` 等），并可同时写入 `thing_model` 快照。
2. **定义物模型**：在产品下增删改属性 / 服务 / 事件（见《物模型定义文档》与《CRUD 接口文档》）。
3. **挂载设备**：基于该产品创建具体设备（F4 设备管理，后续实现）。
4. **运行**：设备按物模型上报属性、响应服务调用、触发事件。
5. **迭代**：可更新产品元数据与物模型（平台约定"改模型需同步维护关系表与 JSON 快照"）。

---

## 6. 存储与代码位置

- 数据库表：`products`（`db/init_iotcloud.sql` 中定义，含 `thing_model` JSON 列）
- ORM 模型：`app/models/product.py` → `class Product`
- 业务接口：`app/api/product.py` → `product_bp`
