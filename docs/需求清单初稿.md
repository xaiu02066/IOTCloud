## 1. 项目背景与目标

### 1.1 背景
智慧农业通过物联网手段对温室、大棚、田间环境进行实时感知与自动化调控。本平台面向**环境监控**场景，采集温湿度、光照、土壤墒情等数据，并提供设备接入、远程控制、数据可视化与告警能力，降低人工巡检成本，提升农业生产精细化管理水平。

### 1.2 目标
构建一个可运行的物联网云平台，支持：
- 多产品 / 多设备的统一接入与生命周期管理；
- 基于"物模型"的设备能力抽象（属性 / 事件 / 服务）；
- 遥测时序数据的上报、存储与查询；
- 平台对设备的指令下发与回执闭环；
- 面向管理人员的可视化看板与阈值告警；
- 基于 JWT + RBAC 的账号与权限体系。

### 1.3 术语
| 术语 | 说明 |
| --- | --- |
| 产品（Product） | 一类设备的逻辑模板，含产品标识（productKey）与物模型 |
| 设备（Device） | 产品下的具体物理/虚拟终端，拥有唯一设备名与密钥 |
| 物模型（Thing Model） | 设备的数字孪生定义：属性、事件、服务 |
| 属性（Property） | 设备可读/可写的状态量（如温度、湿度） |
| 事件（Event） | 设备主动上报的信息（如告警、离线） |
| 服务（Service） | 平台可调用的设备能力（如下发开关指令） |
| 遥测（Telemetry） | 设备周期性上报的时序数据 |
| JWT | 无状态鉴权令牌 |

## 3. 详细功能需求

### F1 用户管理 — 注册 / 登录
- **功能描述**：提供用户注册与登录能力，登录成功后返回 JWT（access + refresh），用于后续所有接口鉴权。
- **用例**
  - 新用户注册账号；
  - 已注册用户凭账号密码登录；
  - Token 临近过期时刷新。
- **输入 / 输出**
  - 注册：`{username|email, password}` → `{userId, username}`；
  - 登录：`{account, password}` → `{accessToken, refreshToken, expiresIn, userInfo}`。
- **业务规则**
  - 用户名 / 邮箱全局唯一；
  - 密码使用加盐哈希（bcrypt / argon2）存储，禁止明文；
  - accessToken 有效期建议 2h，refreshToken 建议 7d；
  - 连续登录失败达到阈值（如 5 次）临时锁定。
- **接口建议**：`POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/refresh`。
- **验收标准**：可完成注册与登录并获取 JWT；错误密码被拒绝；Token 过期后可通过 refresh 续期；未携带有效 Token 的接口返回 401。

### F2 产品管理 — 产品 CRUD
- **功能描述**：产品是设备的逻辑分组模板，承载产品标识与默认接入协议、物模型引用。
- **用例**：创建 / 查询 / 修改 / 删除产品。
- **输入 / 输出**
  - 创建：`{name, productKey?, protocol, description}` → `{productId, productKey, ...}`；
  - 列表 / 详情 / 更新 / 删除对应标准 CRUD。
- **业务规则**
  - `productKey` 全局唯一，可由系统自动生成或用户自定义（需校验格式）；
  - 删除产品前，若存在关联设备应拦截或提示级联影响；
  - 产品可关联一个物模型（F3）。
- **接口建议**：`/api/products`（GET/POST/PUT/DELETE）。
- **验收标准**：产品的增删改查均可用；重复 `productKey` 被拒绝；产品列表支持分页。

### F3 物模型 — 属性 / 事件 / 服务定义
- **功能描述**：为产品定义数字孪生能力，包含三类元素：
  - **属性**：可读 / 可写状态量（如温度、湿度）；
  - **事件**：设备主动上报的信息（如越限事件、离线事件）；
  - **服务**：平台可调用的能力（如下发风扇/阀门开关）。
- **用例**：为某产品添加"温度""湿度"属性与"开关控制"服务。
- **数据结构**
  - 属性：`{identifier, name, dataType, rw(读写权限), unit, min, max}`；
  - 事件：`{identifier, name, outputParams[]}`；
  - 服务：`{identifier, name, inputParams[], outputParams[]}`。
- **业务规则**
  - `identifier` 在同一产品内唯一；
  - 属性区分只读（传感器上报）与读写（可下发）；
  - 服务定义决定 F6 指令下发的参数结构。
- **接口建议**：`/api/products/{pid}/model`（GET/POST/PUT/DELETE）。
- **验收标准**：可定义温湿度属性与开关服务；物模型可被设备接入（F4）与控制（F6）正确引用。

### F4 设备管理 — 注册 / 启停 / 删除
- **功能描述**：管理设备全生命周期：注册（绑定产品）、启用、停用、删除、查看状态。
- **用例**
  - 在某产品下创建设备，系统生成设备名与设备密钥；
  - 临时停用异常设备，恢复后启用；
  - 报废设备并删除。
- **输入 / 输出**
  - 注册：`{deviceName, productId, description?}` → `{deviceId, deviceName, deviceSecret, status}`；
  - 启停 / 删除：状态变更或资源移除。
- **业务规则**
  - 设备密钥安全存储，仅注册时明文返回一次；
  - 停用设备应拒绝接收遥测与下发指令；
  - 删除设备需二次确认，并清理其时序数据保留策略（可选）。
- **接口建议**：`/api/devices`（GET/POST/PUT/DELETE）、`POST /api/devices/{id}/enable|disable`。
- **验收标准**：设备可注册并与产品关联；停用后不再接收数据 / 指令；设备列表可筛选状态。

### F5 时序数据 — 上报入库 / 查询
- **功能描述**：设备通过 MQTT 等协议上报遥测数据，平台解析后写入时序数据库（InfluxDB）；并提供按设备 / 时间范围的查询。
- **用例**
  - 设备周期性上报温湿度；
  - 平台查询某设备最近 24h 曲线、当前最新值。
- **输入 / 输出**
  - 上报（MQTT 主题，如 `product/{pk}/device/{dn}/upload`）：`{ts, properties:{temperature, humidity}}`；
  - 查询：`GET /api/telemetry?deviceId=&metric=&from=&to=` → 时序点数组。
- **存储设计**
  - InfluxDB：`bucket` 按环境/产品划分；`measurement` = productKey；`tag` = deviceName；`field` = 各指标。
- **业务规则**
  - 仅启用的合法设备可写入；
  - 数据写入需校验 productKey / deviceSecret（或 Token）；
  - 建议按时间保留策略（如热数据 30 天、冷数据归档）。
- **接口建议**：上报经 MQTT Broker 桥接至后端消费；查询经 REST 暴露。
- **验收标准**：数据可实时写入 InfluxDB；按设备 + 时间范围查询正确；大数据量下近时效查询响应 < 1s。

### F6 设备控制 — 指令下发 / 回执
- **功能描述**：平台基于物模型"服务"向设备下发指令（如开关），设备执行后回执，形成闭环。
- **用例**
  - 用户在界面点击"开启风扇"，平台下发开关指令；
  - 设备回执执行结果，超时未回执则标记失败。
- **流程**
  1. 平台调用 `POST /api/devices/{id}/commands`，按物模型服务组装参数；
  2. 经由 MQTT 下行主题推送到设备；
  3. 设备执行后上行回执（含 `messageId`）；
  4. 平台更新指令状态（成功 / 失败 / 超时）。
- **业务规则**
  - 每条指令带唯一 `messageId`，用于关联回执；
  - 超时（如 10s）未回执记为失败，可重试（限次）；
  - 仅启用设备可接收指令。
- **接口建议**：`POST /api/devices/{id}/commands`、`GET /api/devices/{id}/commands/{msgId}`。
- **验收标准**：指令可达设备并收到回执；异常（离线/超时）有记录与状态标记。

### F7 可视化 — 看板 / 曲线 / 仪表盘
- **功能描述**：前端基于 ECharts 展示实时监控看板、历史曲线与仪表盘。
- **用例**
  - 单设备实时温湿度曲线；
  - 多设备总览看板；
  - 阈值仪表盘（如当前温度与上限对比）。
- **输入 / 输出**
  - 输入：设备选择、时间范围、刷新频率；
  - 输出：折线图、仪表盘、数字卡片。
- **技术建议**
  - 前端：Vue3 / React + ECharts；
  - 实时数据：WebSocket 订阅设备最新值；
  - 历史数据：调用 F5 查询接口。
- **验收标准**：曲线 / 仪表盘正确渲染；实时数据自动刷新；多设备视图可切换。

### F8 告警 — 规则 / 触发 / 记录
- **功能描述**：提供阈值告警引擎，用户配置规则，数据流入时评估并触发告警，记录告警流水。
- **用例**
  - 配置规则"温度 > 30℃ 持续 5 分钟 → 严重告警"；
  - 越限触发，生成告警记录可供查询。
- **输入 / 输出**
  - 规则：`{metric, operator(>,<,=,between), threshold, duration, level, action}`；
  - 记录：`{ruleId, deviceId, value, triggeredAt, level, status}`。
- **业务规则**
  - 规则绑定到产品 / 设备或全局；
  - 支持持续时长（防抖）避免抖动产告警；
  - 触发后可执行动作（记录 / 通知 / 联动控制，初稿建议至少"记录 + 界面提示"）。
- **接口建议**：`/api/alert-rules`（CRUD）、`/api/alerts`（查询）。
- **验收标准**：规则可配置；越限正确触发并落库；告警历史可按设备 / 时间查询。

### F9 权限 — RBAC 拦截
- **功能描述**：基于角色的访问控制，在网关 / 接口层对资源进行角色 / 权限拦截。
- **用例**
  - 普通用户仅能查看自己名下产品 / 设备；
  - 管理员拥有全部操作权限；
  - 未登录或越权访问返回 403。
- **模型**：用户 — 角色 — 权限；JWT 携带 `userId` 与 `roles`。
- **权限项示例**：`product:manage`、`device:control`、`alert:config`、`user:admin`。
- **业务规则**
  - 公共接口（登录、注册）免鉴权；
  - 数据级权限：普通用户仅访问归属资源（行级隔离）；
  - 角色可配置，默认预置"管理员 / 普通用户"。
- **接口建议**：鉴权中间件统一拦截；权限元数据可配置化。
- **验收标准**：未登录返回 401；越权返回 403；不同角色看到的功能与数据范围正确。

## 4. 非功能性需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 支持 ≥ 1000 台设备并发接入；时序写入 ≥ 500 点/秒；近 24h 数据查询响应 < 1s |
| 安全 | 全站 HTTPS；JWT 鉴权；密码加盐哈希；设备密钥不明文落库；RBAC 行级隔离 |
| 可靠性 | 关键服务可水平扩展；MQTT Broker 集群化；写入具备重试与削峰 |
| 可用性 | 平台可用性 ≥ 99.5% |
| 可维护性 | 统一日志、接口文档（OpenAPI）、基础监控（QPS / 写入延迟 / 设备在线数） |
| 兼容性 | 支持 MQTT 3.1.1/5.0；前端主流浏览器；移动端自适应（建议） |
| 可扩展性 | 物模型驱动，新增设备类型无需改代码；存储可按产品分桶 |

## 5. 技术架构建议（参考）

```
设备(传感器/控制器)
   │  MQTT(TLS)
   ▼
EMQX(MQTT Broker) ──桥接──▶ 后端服务(认证/设备/物模型/控制)
                                │
            ┌───────────────────┼───────────────────┐
            ▼                   ▼                   ▼
        MySQL(业务/用户/        InfluxDB(时序)      Redis(缓存/Session)
        产品/设备/权限)                                │
            │                                        │
        前端(Vue3+ECharts) ◀── REST / WebSocket ──────┘
```

- **后端**：Python + **Flask**（用户指定）
  - 推荐组件：以 Blueprint / Flask-RESTful 组织接口；`Flask-JWT-Extended` 实现 F1 的 JWT 鉴权与刷新；`Flask-SQLAlchemy` + `PyMySQL` 操作 MySQL（用户 / 产品 / 设备 / 权限等业务数据）；`paho-mqtt` 订阅 EMQX 主题、消费设备上报并写入 InfluxDB（F5）；`Flask-SocketIO` 向 F7 前端推送实时数据；`Flask-Caching` / Redis 做缓存与限流；`Flask-CORS` 放开前端跨域。
- **消息**：EMQX（MQTT Broker）
- **存储**：MySQL（业务数据） + InfluxDB（时序数据） + Redis（缓存 / 限流）
- **前端**：Vue3 + ECharts；实时用 WebSocket（SocketIO 客户端）
- **部署**：Docker / Docker Compose（Flask 应用容器化），后续可上 K8s

## 7. 风险与待确认事项

1. 设备侧协议：确认上报采用 MQTT 还是 CoAP / HTTP；是否需兼容 Modbus 网关。
2. 数据保留策略：时序数据热/冷分层与归档周期待定。
3. 部署环境：本地服务器 / 云（阿里云物联网平台） / 自建，影响 EMQX 与 InfluxDB 选型。
4. 多租户：初稿按单租户设计，是否需多租户隔离待确认。
5. 告警动作：初稿仅"记录 + 界面提示"，是否接入短信 / 邮件 / 微信通知需确认。
